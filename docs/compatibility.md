# S3 compatibility and acceptance matrix

The upstream baseline is [`cloudlena/s3manager` v0.13.0](https://github.com/cloudlena/s3manager/releases/tag/v0.13.0), commit [`371dda8ee8e404a05e27115fc20994021959024b`](https://github.com/cloudlena/s3manager/commit/371dda8ee8e404a05e27115fc20994021959024b). The upstream column reflects inspection of the [release README](https://raw.githubusercontent.com/cloudlena/s3manager/v0.13.0/README.md) and [configuration entry point](https://raw.githubusercontent.com/cloudlena/s3manager/v0.13.0/main.go). Garage expectations come from its [v2 S3 compatibility reference](https://github.com/deuxfleurs-org/garage/blob/main-v2/doc/book/reference-manual/s3-compatibility.md). The tables first describe the acceptance cases. Observations from actual runs follow.

## Connections, credentials and controls

| Case | Upstream baseline | CDN Manager acceptance check |
| --- | --- | --- |
| C1. Source selection and endpoint | Numbered `S3_n_*` connections, with a legacy unnumbered single source. `NAME`, `ENDPOINT` and `REGION` identify and route connections. | Configure two distinct source IDs with the same bucket and object names and different contents. Browse and download each through the normal entry point. Confirm a user assigned only one source receives a denial on direct requests to the other, and that list failure on one source leaves the other usable. Legacy upstream environment syntax is a configuration difference. |
| C2. Addressing | `BUCKET_LOOKUP` accepts `Auto`, `DNS` and `Path`. | Exercise a path-style endpoint and a DNS/TLS fixture with a certificate for bucket-prefixed names. Record how the client chooses addressing with no override. Garage documents path and virtual-host styles. |
| C3. Credentials and signing | Static keys, IAM via `USE_IAM` and optional `IAM_ENDPOINT`, signed `V2`, `V4`, `V4Streaming`, and unsigned `Anonymous`. | Exercise static SigV4 on Garage. On capable fixtures exercise workload credentials, streaming request signing, and an explicitly configured read-only unsigned source if implemented. Check IAM endpoint override and legacy SigV2 separately. Garage lacks SigV2, and signed streaming and credential discovery require independent evidence. Any unimplemented mode remains a parity gap. |
| C4. TLS and transport | `USE_SSL`, `SKIP_SSL_VERIFICATION`, `TIMEOUT`, `PORT`, `ROOT_URL`. | Use HTTPS with a trusted certificate and confirm that a bad certificate fails. Record support for HTTP in local fixtures, timeout configuration, listen address and reverse-proxy subpaths. An insecure TLS bypass is an upstream option whose availability must be recorded explicitly. |
| C5. Bucket scope and read-only access | `BUCKETS` adds explicit buckets to discovery, including unsigned sources. `BUCKET_NAME` filters navigation. `ALLOW_DELETE` controls deletion. | Use an allowed bucket, an unlisted bucket accessible to a test S3 key, and a bucket the test key cannot access. Check listing and direct REST and MCP read, write, and delete with viewer, editor, and admin roles. Check denial when role or MCP scope lacks a required permission. CDN Manager requires server-side bucket restrictions. |

## Operations and provider capabilities

| Case | Upstream baseline | CDN Manager acceptance check |
| --- | --- | --- |
| O1. Buckets | List, create and delete empty buckets. Read and edit bucket policy. | Create and list a fresh allowed bucket with a privileged test identity. Confirm deletion fails while it contains objects and succeeds after emptying. Garage supports bucket operations with appropriate key permissions and lacks S3 bucket policies. On an isolated AWS S3 general-purpose test bucket, round-trip a narrowly scoped policy granting access to a dedicated test principal. Verify that a source with policy management disabled rejects direct requests even with an administrative app role. |
| O2. Prefixes and paging | Hierarchical view and `LIST_RECURSIVE`. Default listing is paged by S3. Search, custom sorts, show-all and version views scan a bounded set of up to 10,000 entries. `TZ` controls display. | Seed more entries than one S3 page and more than the application scan limit, including nested keys. Traverse continuations and compare all keys with fixtures. Verify delimiter boundaries, recursive behavior, search/sort order within the scan, and disclosure when results are incomplete. Record the timestamp display behavior and the configured scan limit. |
| O3. Upload, preview and downloads | Single file and folder upload, browser opening, single download, ZIP for selections. | Upload a folder containing `drafts/猫 photo #1%25.txt` and a second file with the same basename in another folder. Compare hashes after single download and ZIP extraction. Validate relative ZIP paths, streaming with a payload above the app memory budget, and isolation of HTML and SVG previews from the manager session origin. |
| O4. Deletion | Individual and bulk deletion, including folder operations when permitted. | Delete one fixture. Submit a bulk request containing a key the fixture denies alongside permitted keys, or use a deterministic provider fixture that emits an S3 per-key error. Verify per-object outcomes, presence of the rejected key, and removal of successful keys. If recursive deletion is offered, verify that neighboring prefixes survive. |
| O5. Metadata and versions | `SHOW_METADATA` gates system/user metadata. `SHOW_VERSIONS` controls version listings and explicit historical downloads. | Seed known `Content-Type` and user metadata and compare with object details. On AWS S3 general-purpose storage with versioning enabled, write two distinct values under one key, capture both version IDs, and download each version. Garage lacks S3 object versioning. Verify that Garage capabilities suppress version operations and direct version requests return an explicit unsupported result. |
| O6. Links | `PUBLIC_URL` customizes object links. `PRESIGN_URL` chooses a separate signing endpoint when configured. Upstream checks public reachability and issues temporary download links. | Verify that UI and MCP generate identical CDN URLs and that identical keys in different configured buckets produce distinct URLs. Fetch the encoded key from the public gateway and verify unsigned origin access fails. Create a short-lived S3 link with an authorized role, verify it from a reachable recipient network before and after expiry, and check denial without presign permission. If a separate signing endpoint is offered, verify the signed host reaches S3 unchanged. Garage documents presigned URLs. |
| O7. Encryption | Unspecified encryption and `SSE`, `KMS`, `SSE-C`, with `SSE_KEY` for KMS and SSE-C. Upstream SSE-C public and presigned browser links lack the required customer-key headers. | On isolated fixtures, upload and read with default encryption, explicit SSE-S3, SSE-KMS with a dedicated key, and SSE-C with a throwaway key. Verify server-side metadata and successful reads with correct credentials. For SSE-C, verify failed reads without the headers and verify that any disabled share actions explain the restriction. Garage documents SSE-C. Validate SSE-S3 and SSE-KMS independently before advertising those capabilities. Mark each unavailable app mode as a parity gap. |

## CDN Manager extensions

| Case | Acceptance check |
| --- | --- |
| E1. Atomic text save | On each target Garage build, run the probe below. In two browser sessions read the same revision, save two distinct edits, and verify one winner, one visible conflict and retention of the losing draft. Repeat via REST and MCP with the stale validator. Enforce the text-size ceiling at the API and validate allowed content. |
| E2. Resumable multipart | Upload a valid MP4 larger than the app memory limit using several parts. Interrupt one part, restart the app, and reconcile with provider `ListParts`. Verify only unfinished parts are sent again, content checksum matches, peak memory stays within the limit, and a second subject cannot query, upload, abort, or complete that session. Lose the first completion response and verify retry returns the same result. Abort or expire a second session and verify provider cleanup. Garage lists the required S3 multipart endpoints. |
| E3. Independent public streaming | Route a fixture such as `https://files.example.com/video/{key}` through a gateway with a private origin. Check the exact legacy key `video` and prefix `video/` for collisions on the existing origin before enabling that route. On the new route request a nested key that itself starts with `video/`, verifying the gateway removes only the routing prefix. From a separate network request a byte range on a cold cache and verify `206`, `Content-Range`, and bounded origin bytes. Repeat while the app restarts. |
| E4. Authenticated entry points | Sign in through the browser and a real MCP client with the same identity. Verify source lists and link equality. Exercise denied direct requests for missing roles or scopes, expired credentials and wrong audience. Verify mutation audit entries include subject, client, object and outcome and exclude credentials and signed URLs. |

## Atomic write probe

Run against a dedicated test bucket using preconfigured AWS CLI profiles and an exact provider version. The CLI version must support `s3api put-object --if-match`. Configure path addressing for a path-style endpoint. In separate CLI processes use the same quoted ETag and distinct payloads. Repeat with fresh keys and through distinct replicas where the deployment exposes more than one S3 endpoint. The test fixtures are locally prepared files, and `compat/conditional.txt` is disposable.

```sh
# Configure S3_TEST_ENDPOINT, AWS_PROFILE, AWS_DEFAULT_REGION and TEST_BUCKET.
aws --endpoint-url "$S3_TEST_ENDPOINT" s3api put-object \
  --bucket "$TEST_BUCKET" --key compat/conditional.txt --body initial.txt
etag=$(aws --endpoint-url "$S3_TEST_ENDPOINT" s3api head-object \
  --bucket "$TEST_BUCKET" --key compat/conditional.txt --query ETag --output text)
aws --endpoint-url "$S3_TEST_ENDPOINT" s3api put-object \
  --bucket "$TEST_BUCKET" --key compat/conditional.txt --if-match "$etag" --body first.txt >first.log 2>&1 &
first_pid=$!
aws --endpoint-url "$S3_TEST_ENDPOINT" s3api put-object \
  --bucket "$TEST_BUCKET" --key compat/conditional.txt --if-match "$etag" --body second.txt >second.log 2>&1 &
second_pid=$!
wait "$first_pid"; first_status=$?
wait "$second_pid"; second_status=$?
printf 'first=%s second=%s\n' "$first_status" "$second_status"
aws --endpoint-url "$S3_TEST_ENDPOINT" s3api get-object \
  --bucket "$TEST_BUCKET" --key compat/conditional.txt downloaded.txt
```

Require exactly one successful write, an explicit precondition failure or conditional race from the loser, and downloaded contents equal to the winner. Retry the losing write with the stale ETag and require precondition rejection again. [AWS documents conditional writes for general-purpose S3 buckets](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html). The inspected [Garage `PutObject` handler](https://github.com/deuxfleurs-org/garage/blob/main-v2/src/api/s3/put.rs) provides no evidence of atomic `If-Match` enforcement. Keep conflict-safe editing off for an unverified source. A separate `HeadObject` followed by an unconditional write leaves a race between the requests.

## Recording results

Record each case by application revision, provider build, capability settings, test identity role, caller (browser, REST, MCP or gateway), observed result and evidence reference. Use **PASS**, **FAIL**, **BLOCKED**, **unsupported by provider** or **parity gap** for individual observations. A capability is supported by the application only after it passes through the relevant normal entry point on a provider that implements it. Keep live configuration, credentials and signed URLs out of public evidence.

## Independent local acceptance

The 2026-11-27 run used Ubuntu WSL2 on linux/amd64 with Go 1.26.5 and the INFRA-5 working tree based on `7f1307e71c3622e004dc035d49be2d58ee3bf7e7`. The local Compose stack used Garage 2.3.0, the two NGINX S3 gateways, and the bundled loopback OAuth issuer. Source IDs were `assets` and `media` with separate bucket allowlists.

| Case | Outcome | Evidence |
| --- | --- | --- |
| C1, C2, C3, C4 | **PASS** for two sources, path-style static SigV4, HTTP transport on the local fixture. | An external Go SDK client and direct REST wrote `receiver/<run>/special 猫 #50%.txt` to both sources and got the respective distinct bodies via their CDN URLs. Virtual-host TLS, bad certificates, and reverse-proxy subpaths require separate fixtures. |
| C5 | **PASS** for exercised source, bucket, role and scope boundaries. | Owner and editor listed both sources. Viewer listed and read only Assets. Direct requests with a known hidden source ID or mismatched bucket failed through both REST and MCP. REST denied viewer PUT, editor DELETE, and owner PUT without CSRF. An owner with a read-only MCP access token could not start an upload. |
| O1, O5 | **PASS** for Garage capability gating. | REST returned 422 for bucket policy and versions requests from the owner on Media with both capabilities disabled. Bucket lifecycle, policy round-trip and historical bodies on a capable provider are separate checks. |
| O3 | **PASS** for browser file/folder uploads and REST ZIP path preservation and contents. | Chromium uploaded a CSS file through the Assets file picker and a nested MP4 through the Media folder picker. An independently extracted REST ZIP entry had the exact Unicode key as its relative path and the expected payload. |
| O6 | **PASS** for distinct permanent links across sources, exact UI/REST/MCP equality and availability reporting. | Both same-key URLs opened anonymously through NGINX with the expected bodies. Chromium clipboard matched the MCP link. The object card returned “Checked from the manager · Available · HTTP 200” while S3 was private. |
| E1 | **FAIL** for provider enforcement on Garage 2.3.0, with application writes gated. | `TestS3Integration/ConditionalWrites` sent an S3 `PutObject` with the ETag captured before a distinct replacement. Garage accepted the stale write. The application test also verified that disabled conditional writes return unsupported. |
| E2 | **PASS** for browser restart and resume, direct provider recovery, expiration, and SDK transfer. | Chromium uploaded a 75,497,472-byte MP4 through the read-only manager container running as UID 65532 with a 67,108,864-byte memory limit. Part 2 was interrupted. After restart Garage reported only part 1, which was transmitted exactly once. Retried completion and status returned consistent results. The S3 integration also recovered a provider-completed upload and confirmed expired sessions were removed from Garage. | E3 | **PASS** for local gateway independence, one-prefix stripping and cold range. | With the manager stopped, an anonymous range on a key starting with `media/` at the public route `/media/media/…` returned 206, `Content-Range: bytes 0-4095/75497472` and the exact 4,096 bytes. | E4 | **PASS** for the demo issuer over actual HTTP. | Independent external client used the official MCP Go SDK to establish Streamable HTTP sessions with signed tokens from the demo issuer's Authorization Code + S256 exchange. A correctly signed token for the second registered client failed audience validation. `go test -count=1 -race ./...` also passed, including tests for browser callback replay, state/nonce, expiry and wrong issuer. |

The Garage probe ran with `CDN_MANAGER_TEST_S3_CONDITIONAL_WRITES=ignored go test -count=1 -race -v ./internal/storage`. Set `CDN_MANAGER_TEST_S3_ENDPOINT`, `CDN_MANAGER_TEST_S3_REGION`, `CDN_MANAGER_TEST_S3_BUCKET`, `CDN_MANAGER_TEST_S3_ACCESS_KEY` and `CDN_MANAGER_TEST_S3_SECRET_KEY` to an isolated Garage fixture. Use `required` on a provider expected to enforce stale ETags.

The independent Chromium run used `web/tests/compose.spec.ts` with the commands in [local end-to-end acceptance](../e2e/README.md). It completed in 23.9 seconds. The tested manager image was `sha256:b65108bab38775460650261b2b52dd865368d16d1f4bf8e512f596de5184f5cb`. At 1440 pixels the object table retained separate size, modified and CDN link columns. The paused transfer showed 8 of 72 MiB completed, the interruption message and the Resume and Abort controls at all three widths. ### Additional provider and real Authentik

The second fixture used [SeaweedFS 4.55](https://github.com/seaweedfs/seaweedfs/releases/tag/4.55), build `a98c9e271`, with static credentials, path-style addressing and `listingEncoding: form`. Its manager listened on a separate loopback port and used Authentik 2026.8.7 with separate confidential web and public MCP applications. The tests below used a disposable bucket for policy and deletion checks and a separate versioned bucket.

| Case | Outcome | Evidence |
| --- | --- | --- |
| C1, O1 | **PASS** after source health fix. | A source with bucket management and an absent allowlisted bucket previously showed “unavailable” despite successful writes to its existing bucket. After rebuilding, the same fixture reported SeaweedFS healthy, a second unreachable source unavailable, and `/readyz` returned 200. REST created and listed the reserved bucket, received 409 deleting it while nonempty, and removed it after emptying. |

Repeat SeaweedFS key, multipart and stale ETag checks with `go test -count=1 -race -v ./internal/storage` and the fixture variables above, setting `CDN_MANAGER_TEST_S3_LISTING_ENCODING=form` and `CDN_MANAGER_TEST_S3_CONDITIONAL_WRITES=required`. Use SeaweedFS 4.55 in `weed mini` mode with a loopback S3 bind and a dedicated bucket. The repository's Go integration test covers both listing encodings and the browser tests cover UI conflict feedback and CDN status. The additional live provider checks use the routes in the OpenAPI contract, and the tested Inspector command and Authentik configuration are in [Connect MCP Inspector through Authentik](mcp-authentik.md).

Known application **parity gaps** from configuration and client inspection include AWS credential discovery and IAM endpoint override, SigV2, SigV4 streaming signing, unsigned sources, an insecure TLS override, a separate presigning endpoint, and explicit SSE-S3, SSE-KMS or SSE-C controls. The application accepts static keys and an optional session token. The browser uses the viewer's locale and time zone for dates.

**BLOCKED** on the deployment environment are production Authentik, external DNS and TLS, cross-cluster signed reads, collision and capacity checks on the existing bucket, CDN freshness and cache sizing, and production cutover and rollback. The local test provides evidence for the browser, API and MCP path. AWS-specific parity, a published release installation and the deployed alert and cache behavior require separate verification.
